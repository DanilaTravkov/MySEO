# Data model

The MVP schema is split into acquisition, analytics, and opportunity layers. UUIDs are generated by the application, timestamps are timezone-aware, and all persistent schema changes go through Alembic.

```text
Workspace
  └─ DiscoveryRun
       └─ Seed

Keyword
  ├─ KeywordObservation           raw provider snapshot
  │    └─ MonthlySearchVolume     raw provider time series
  ├─ KeywordAnalysis              versioned calculated metrics
  └─ ClusterKeyword ── Cluster
                         └─ Opportunity
                              └─ ProductHypothesis
```

## Acquisition layer

- `workspaces` provides the future multi-workspace ownership boundary. The MVP uses one local workspace.
- `discovery_runs` records provider, locale, lifecycle timestamps, configuration, and controlled errors. A run belongs to a workspace.
- `seeds` preserves the exact seed set for a run; duplicate seed text within the same run is rejected.
- `keywords` stores display text separately from its normalized comparison key. Uniqueness is enforced on `(normalized_text, language, geo)`.
- `keyword_observations` stores immutable provider snapshots and the original payload in `raw_json`. `discovery_run_id` identifies the dataset used for later normalization; it is nullable only for legacy observations created before Stage 4.
- `monthly_search_volumes` belongs to one observation and allows only one value per year/month.

## Analytics layer

`keyword_analyses` contains only derived values. Its composite primary key `(keyword_id, analysis_version)` makes recalculation reproducible without overwriting provider data, while `discovery_run_id` records the percentile-ranking population. Scores are constrained to `0..100`; undefined statistics remain nullable rather than using infinities or sentinel values.

Raw provider fields must never be added to `keyword_analyses`, and calculated metrics must never be written into `keyword_observations`.

## Opportunity layer

- `clusters` groups semantically related keywords per discovery run through `cluster_keywords`; similarity and the configurable threshold are constrained to `0..1`. Each cluster stores total and median volume, volume-weighted growth, median competition, median bid, and keyword count. Total volume is an aggregated demand signal, not a unique-user estimate.
- `opportunities` stores a versioned score for a cluster. Each component and total is constrained to `0..100`, with recommendation limited to `build`, `consider`, or `skip`.
- `product_hypotheses` stores the structured product proposal and optional Markdown build brief. LLM identifiers are metadata only; secrets are never persisted.

Foreign keys use cascade deletion for records that have no meaning without their parent. Domain history is otherwise preserved through explicit version columns.
